# DeepWhite Studio 需求大纲

更新日期：2026-09-20。依据用户确认的需求、当前实现文件和最近一次验收记录整理。本次为需求与状态梳理，未重新执行全量测试，也未发起真实付费生成。

## 一、产品目标

在干净的原版无限画布基础上建立独立的 DeepWhite 项目，接入自己的 DeepWhite API，让用户在同一画布中组织素材、调用不同模型生成文字/图片/视频，并逐步增加影视制作工具与工作流。画布是创作入口，后续与用户并行开发的导演工具结合。

当前主要交付入口是普通画布；智能画布保留原有能力，但没有承诺与普通画布全部新增功能同步。

## 二、已经确定的设计原则

- 保留原版的基础画布与素材管理能力；扩展前先查原版，优先复用，不重新做一套。
- 界面以文字、图片、视频及后续音频为主；不必要的原版专用节点暂时隐藏。MJ 的专用动作使用独立工具入口。
- 模型同步后自动分类与启用，用户可停用、移除和恢复；再次同步保留这些选择。
- 模型选择为“模型系列 → 具体版本”。不让用户选择 t2i/i2i 等接口名称，根据参考素材自动匹配调用方式。
- 只展示模型实际支持的参数。估价有依据才显示，未知不写成免费；实际费用以平台结算为准。
- 上传图片和生成图片使用统一交互：单击显示上方处理工具栏，双击查看大图；一组结果仍放在一个节点，左右翻页用于大图查看。
- 每次增加一个明确功能，确认操作方式后实施与验收，避免一次塞入大量工具。

## 四、第二阶段：素材处理与制作辅助

已实现第一批：

1. **图片处理工具栏**：标准人设图、裁剪、宫格裁剪、标注、调整尺寸、下载、查看大图。复用原版编辑器；编辑生成图时保留原结果集合。
2. **标准人设图**：以所选单张图片为唯一参考，使用用户提供的完整三联提示词；默认全能图片 G2.5 高品质版，4:3、1K、单张，显示模型与估价。接入模拟测试通过，人物一致性及构图效果尚待实际出图确认。
3. **截取关键帧**：视频播放定位/输入秒数、添加和移除时间点、一次最多 20 帧、本地原分辨率 PNG、保存来源与时间。真实 WebM 截帧测试通过，不消耗生成额度；暂不含自动镜头检测和自动语义选帧。

用户已规划、尚未完成：

- 去字幕。
- 3D 导演台。
- Blender 白模连接与预演。

后续可评估但不视为已批准交付范围：专用人设资产管理、更多人物处理预设、自动关键帧检测、统一素材命名归档。

## 六、基础阶段剩余收尾清单

1. 选代表性的文本、图片、视频和 MJ 型号，做真实接口小样与账单核对；标准人设图单独看人物一致性和三联布局。仍遵守用户暂不消耗额度的要求，未授权前不自动执行。
2. 验证真实大图、视频/音轨、完整下载及批量下载。现有真实 WebM 截帧验证只覆盖其中一部分。
3. 验证较大画布、多任务并行、长时间等待、网络断开、电脑休眠、多标签页同时编辑。
4. 核对复杂分组、重做、全部组合快捷键、导入导出往返、不同浏览器和触屏。原版存在或保留，不等于已经完整验收。
5. 建立实际要使用的模型清单，逐型号标明“已适配/已模拟验收/已真实验收”；当前仍有专用协议未适配的型号。
6. 确认普通画布作为当前主入口，避免把早期交互稿或智能画布当成完全相同的产品界面。

## 七、完成标准与建议顺序

每个功能应满足：入口清楚 → 输入与参数明确 → 请求正确 → 状态可见 → 结果可保存和复用 → 失败能理解并处理。

“已实现”表示代码和入口存在；“模拟验收通过”表示请求与交互通过隔离测试；“真实验收通过”还需要实际模型结果及费用核对。三者分开记录。

建议先收尾基础使用与真实媒体验证，整理问题清单；在允许额度后做代表模型真实验收，再逐项增加去字幕、3D 导演台和 Blender 白模。不要为推进阶段而忽略已有操作问题。
