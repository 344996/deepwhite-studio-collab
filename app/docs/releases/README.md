## 后续每次更新的做法

1. 开发前记录备份位置和范围；不要公开含密钥或私人素材的备份。
2. 根据真实改动确定版本号，使用[版本文档模板](TEMPLATE.md)编写独立版本说明。
3. 从上一版复制累计功能清单，逐项更新状态，保留未完成项；被取消或暂缓的需求注明原因，不悄悄删除。
4. 写清本次新增、修复、入口、验证证据、真实调用是否执行、已知限制、数据兼容及恢复方式。
5. 同步 VERSION、CHANGELOG、本索引和项目 README 当前版本链接；设计版本单独管理。
6. 发布前核对文档与运行版本一致。已发布历史保持当时语境，后补更正标明日期。

状态固定为：**已实现**、**部分实现**、**未实现**、**暂缓**；验证单独记录，不能将“已实现”等同于全部真实环境验收通过。
