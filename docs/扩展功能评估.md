## 微信登录

建议把微信开放平台应用与回调服务放在 API 网站。本地软件打开网站登录页，网站校验授权结果后，用有时效、一次性的票据交给本地会话；校验随机 state、请求来源及票据归属。AppSecret 只保存在网站服务端，不能写入公开仓库或下载客户端。账户绑定、解绑、已有账号合并和失效重登需要明确产品规则。

实施前需要确认网站应用资格、已审核的应用、可用的 AppID/AppSecret、回调域名和网站后端修改权限。官方网站文档本轮访问失败，因此没有把主体要求、认证金额或审核时长写成已经核实的承诺；应在实施前查看 [微信开放平台](https://open.weixin.qq.com/) 和 [网站应用微信登录文档](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)。

验收应包含扫码取消、二维码过期、重复领取、state 不匹配、绑定冲突、网站不可达以及退出登录。第三方身份服务和本地会话需要分开，不应把扫码成功当作获得模型服务密钥。

## 画廊

建议先保留本地资产管理作为个人作品库。如果目的是公开展示、传播和分享，公共画廊放在网站更合适，本地软件提供“选择作品 → 确认公开范围 → 发布”的入口。这是基于当前本地存储和账号架构的工程建议。

最小公共画廊包括作品列表、详情、作者、封面、标签、搜索、删除/撤回和发布状态。后端需要对象存储、缩略图处理、上传大小限制及审核流程。发布前让用户选择是否包含提示词、节点参数和参考素材；默认不上传完整画布、密钥或本地文件路径。下载到本地后仍以资产版本记录来源。

持续费用可以按“存储量 × 存储单价 + 下行流量 × 流量单价 + 审核及服务器”估算。需要预期作品数、平均视频体积和月访问量才能给可靠月费；本轮没有替用户采购云服务。

## 在线更新

现有 `studio_server.py` 明确阻止原上游覆盖式更新；这个保护应保留。新仓库需要自己的更新协议：版本号、系统架构、最低兼容版本、包 URL、SHA-256、签名、变更记录、数据迁移版本及回退能力。只有哈希还不够证明发布者身份，应验证可信签名或来源证明。

推荐流程：检查版本 → 用户确认 → 下载到临时目录 → 校验 → 保存工作并停止本实例 → 安装到新的版本目录 → 启动与 health 检查 → 切换当前版本。失败时回退程序目录；数据迁移应有独立快照和兼容策略。用户数据、API 配置和素材目录不能放进覆盖更新的程序包。

GitHub Releases 可作为发布源。GitHub 提供不可变发布来保护已发布标签和附件；是否启用、如何验签及国内下载可用性仍需在发行阶段验证。[GitHub 不可变发布说明](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases)

验收包括下载中断、包损坏、签名失败、磁盘不足、文件被占用、启动失败、旧数据升级和回退。当前仓库只提供源码启动依赖，没有完整 Windows 安装器；不能直接把 `git pull` 当作用户在线更新。

## MCP 和 Codex

**2026-10-18 实施更新**：用户确认继续当前完整项目后，0.10.2-studio.14 已新增四个工具（项目列表、节点约束、创建画布、结构编辑），支持普通画布文字/移动/连线及最新编辑撤销。实际本机 MCP 到浏览器闭环已验证；尚不包括任意节点、智能画布、项目管理和真实 Codex 配置联调。下文保留初始九工具基础与原评估，当前结果见[开发报告](项目完整迁移与MCP开发.md)。

项目已有 `app/studio_mcp.py` 的 stdio 桥接、`studio_control.py` 的本机授权入口和九个工具定义：`list_canvases`、`get_canvas`、`list_models`、`list_assets`、`apply_nodes`、`undo_edit`、`generate_node`、`get_generation`、`resume_generation`。

已有能力能够读取画布、读取模型和资产，以及有版本校验地写入受支持的图片/视频节点；生成操作保留审批或限时授权。它不是完整的通用画布控制 API：项目管理、创建画布、任意节点类型、通用连线创建/删除、移动与删除节点仍需独立补充并验收。

建议依次扩展：只读项目和节点 schema → 创建画布及文字节点 → 受约束的节点修改和连线操作 → 撤销/冲突检查 → 调用已有工具。每次写入必须有 `expected_revision` 和幂等操作 ID，禁止随意写任意文件、读出 API 密钥或自动开启付费生成。工具返回值和画布文本属于数据，不得当作更高权限指令。

连接配置应由软件的“本地智能体/MCP”设置生成，客户端只启动本地桥接，使用独立控制令牌。当前桥接声明的协议版本需要与目标 Codex 客户端实际协商验证；本轮没有改动用户的 Codex 配置，也没有声称真实客户端联调通过。MCP 官方安全指南强调本地服务执行权限、最小授权和令牌边界，这些约束应保留。[MCP 安全实践](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

验收包括版本冲突、幂等重试、拒绝越界操作、无权限调用、取消审批，以及生成只提交一次、结果写回正确画布。现有自动化测试是后续扩展基线，不等同于所有 Codex 版本的真实兼容性验收。
