# 意见反馈：使用、接口与扩展

适用：画布 0.11.0-studio.1、画廊 0.4.0。两个服务分别维护数据；不需要把本地画布开放到公网。

## 使用方式

画布设置的“意见反馈”允许先保存本地草稿，再主动发送到已配置的画廊。描述、联系方式和截图均由用户填写或选择；诊断信息是可选项，仅包含版本、平台名称和客户端类型，不自动上传日志、项目内容或 API Key。

画廊管理员登录后打开“用户反馈”，筛选待处理记录、查看截图、回复及修改状态。提交者在画布点击“查询回复”，无需把账号密码或网站会话交给反馈服务。服务器没有部署或断网时，草稿保留，可稍后重试。

截图只接受静态 JPG、PNG、WebP，最多 300 KB、600 万像素；服务端重新编码，去除元数据。识别式凭据清理不能识别任意隐私文字，提交前仍应检查手动填写的内容和截图。

## 修改位置

| 部分 | 位置 | 不应破坏的约束 |
| --- | --- | --- |
| 画布表单和本地记录列表 | `app/static/studio-feedback.html/.js/.css` | 等待截图处理；提交期间锁定输入；失败保留草稿 |
| 画布保存与传输 | `app/studio_feedback.py` | 原子保存后发送，固定接收地址及回执；不会带网站 Cookie 或 API Key |
| 画廊接口 | `gallery/feedback.py`（画廊仓库） | UUID + 私密回执去重；管理员权限；乐观锁 |
| 画廊收件箱 | `gallery/static/feedback.html/.js/.css` | 文本通过 textContent 显示；截图仅管理员读取 |
| 数据迁移 | `gallery/schema.py` | schema 4 事务内追加两张表，保留旧作品 |
| 回归 | `app/tests/test_studio_feedback.py`、`check-feedback-flow.cjs`；画廊 `test_feedback.py`、`test_backup.py` | 断网、重复提交、权限、截图、恢复均需覆盖 |

## 接口

画布端：

- `GET /api/studio/feedback`：本地记录与当前接收站点。
- `POST /api/studio/feedback`：保存不可变草稿；客户端 UUID 相同且内容相同可安全重试，改变内容应使用新 UUID。
- `POST /api/studio/feedback/{id}/send`：发送或重试，首次发送固定站点，不能把同一回执发送给后来替换的站点。
- `POST /api/studio/feedback/{id}/refresh`：查询处理结果；较旧回复不会覆盖较新 revision。

画廊端：

- `POST /api/gallery/feedback`：接收草稿，使用匿名会话 CSRF，限流每 IP 每分钟 6 次，最多 500000 字节 JSON。
- `GET /api/gallery/feedback/{id}`：请求头 `X-Feedback-Receipt` 查询；回执不放进 URL，不作为公开链接。
- `GET /api/gallery/moderation/feedback`：管理员列表，按状态和 offset 翻页。
- `GET /api/gallery/moderation/feedback/{id}/screenshot`、`.../events`：管理员附件与最近 100 条处理事件。
- `PATCH /api/gallery/moderation/feedback/{id}`：`expected_revision`、`status`、`reply`；冲突返回 409，不能覆盖其他管理员回复。

状态为 `new`、`in_progress`、`done`、`closed`。画廊只保存回执摘要，本地服务保留私密回执；公共作品搜索不会展示反馈。反馈截图存入 SQLite，所以原有数据库备份会包含截图、回执摘要及处理记录。

当前画布最多保存 1000 条，服务端最多 2000 条、截图总量 256 MiB。容量满返回可读错误，不自动删除旧反馈。未来增加归档/删除、邮件通知、分配管理员或多实例时，应补权限、保留策略和恢复测试；当前没有自动通知或跨实例共享限流。
