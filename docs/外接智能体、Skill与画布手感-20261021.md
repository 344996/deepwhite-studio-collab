## 1. 参考 LibTV 的画布手感与布局

### 参数从哪里来

LibTV 的画布要微信登录，无法直接操作。这里沿用 REA 逆向分析的做法：打开画布页时，浏览器会下载 LibTV 公开的前端脚本和样式。在页面里对这些文件做静态分析，只提取交互参数和配色令牌，不复制任何代码。

分析结论：LibTV 画布基于 React Flow（xyflow）。

| 项目 | LibTV 实际取值 | 本项目原来 | 本轮改为 |
|---|---|---|---|
| 缩放范围 | `minZoom 0.1`、`maxZoom 8`、默认 1 | 0.06–2.5 | **0.1–8（10%–800%）** |
| 滚轮 / 触控板 | `panOnScroll`：滚动平移；Ctrl/⌘+滚轮、双指捏合缩放 | 纵向滚轮缩放 | **默认滚动平移，Ctrl/⌘ 或捏合缩放**。右下角“鼠标”按钮可切回滚轮缩放，选择会被记住 |
| 平移 | 空格+拖动、中键拖动、H 工具 | 已有 | 保留 |
| 工具 | V 选择 / H 移动 | 已有 | 保留 |
| 快捷键 | `mod+0` 适应、`mod+=`/`mod+-` 缩放、`tab` 新建、`mod+l` 连线、`mod+enter` 生成、`mod+d` 复制、`mod+f` 查找、`mod+g` 分组、Delete/Backspace 删除 | 缺 `mod+0/=/-`（会触发浏览器整页缩放）、Tab、`mod+l`、`mod+enter` | **全部补齐**。Tab 只在焦点位于画布时生效，不影响键盘切换焦点 |
| 双击空白 | 打开添加节点菜单 | 已有 | 保留 |
| 主工具条 | 底部居中浮动：添加 · 历史 · 工具模式 · 快捷键；8px 内边距、12px 圆角 | 左侧竖排工具栏 | **宽度 ≥900px 时改为底部居中浮动**；窄屏仍用左侧栏 |
| 连线 | 2px，`#86909c`，悬停 `#c0c8d0`，选中 `#e0e4e8` | 主题内定义 | 未改，见下方说明 |
| 画布 / 网点 | 背景 `#141414`，点 `#474747`（深色） | 主题网点 | 未改 |
| 节点边框 | `#363636`，选中 `#a8a8a8` | 主题内定义 | 未改 |

为什么不改配色：现有 4 套主题（石墨 / 奶白 / 浅色 / 深色）共用一组 `--dw-*` 令牌。表中的 LibTV 色值留作参考，以后要统一主题时可以直接用。这一轮只改“手感”和布局。

### 改了哪些文件

- `app/static/studio-canvas-v2.js`：缩放上下限、滚轮模式、新快捷键、`connectSelected()`（Ctrl+L，按画布连线规则自动判断方向）、`generateSelected()`（Ctrl+Enter，只生成单个选中节点，与节点上的生成按钮是同一个入口）、快捷键帮助。
- `app/static/studio-canvas-feel.css`：底部居中工具条，由 `studio-canvas-workspace.js` 加载，经典画布和智能画布都生效。
- `app/tests/check-canvas-v2.cjs`、`check-canvas-pointer-safety.cjs`：改为“Ctrl+滚轮缩放、上限 8、下限 0.1”的新约定。

### 怎么验证的

在本机启动的服务里打开真实画布，用脚本模拟输入，结果如下：

- 滚轮平移 y −100，比例不变。
- Ctrl+滚轮放大到 1.22。
- 连续放大停在 8，连续缩小停在 0.1。
- Ctrl+0 / Ctrl+= / Ctrl+- 都拦截了浏览器缩放，视图正确变为 0.372 → 0.447 → 0.372。
- Tab 打开添加菜单。
- 滚轮模式切换会写入本地存储。

没有运行：Playwright 浏览器脚本（这台机器没装 Playwright）。也没有用真实鼠标或触控板做人工手感验收。

## 2. 用户建议怎么收集

原来只有“发送到画廊反馈后台”一个渠道，但画廊还没有部署公网，所以反馈实际发不出去。现在按以下顺序发送，至少一条一定能走通：

1. **画廊反馈后台**：设置了画廊地址时使用，保留原有回执和处理结果查询。
2. **开发者群机器人**：飞书、企业微信、钉钉或通用 HTTPS webhook。配置方式（二选一，都不进仓库）：
   - 复制 `app/feedback_channels.example.json` 为 `app/feedback_channels.json`（已加入 `.gitignore`）；
   - 或设置环境变量 `DEEPWHITE_FEEDBACK_WEBHOOK=feishu|https://open.feishu.cn/...`。
   发送内容包括分类、标题、描述、联系方式、可选的版本与系统信息和反馈编号；截图只保留在用户本机。程序会按飞书、企业微信、钉钉返回的 `code` / `errcode` 判断是否真正送达。
3. **GitHub Issue（兜底）**：前两条都不可用时，打开 `344996/deepwhite-studio-collab` 的“新建 Issue”页面，标题和正文已填好，标签为 `feedback`。用户用自己的账号点提交，程序不代替登录，也不保存任何凭证。

另外，外接智能体可以通过新的 MCP 工具 `submit_feedback` 帮用户提交。Skill 要求先向用户复述内容、得到同意后再提交；返回 GitHub 链接时，由用户自己确认。

- 开发者处理：在群机器人消息或 GitHub Issues（按 `feedback` 标签筛选）里查看。用户本机的“我的反馈”列表会显示每条反馈走的渠道。
- 注意：webhook 地址写进发行包后，拿到安装包的人都能向这个群发消息。建议使用只用于接收反馈的独立机器人。
- 验证：自动化测试覆盖了“无渠道时生成 GitHub 链接”和“模拟飞书 webhook 收到正确内容并标记已发送”。**没有向真实的飞书 / 企业微信 / 钉钉群发送过消息**。

## 3. MCP 无法连接：根本原因与修复

**根本原因**：桥接程序 `studio_mcp.py` 启动时会先检查画布服务，画布没运行就以退出码 2 结束。而 Codex、Claude 等客户端通常在自己启动时就拉起 MCP，那时画布往往还没打开。结果是客户端把服务标记为“连接失败”，之后打开画布也不会自动恢复。上一版加的诊断只是把这个错误讲得更清楚，并没有消除它。

**修复**

- 桥接程序始终保持运行，在每次调用工具时才检查画布。画布重启或更新后，下一次调用会重新检查。
- 新增只读工具 `studio_status`：客户端里的智能体可以自己检查“画布是否运行、MCP 是否启用、授权是否有效”，并把一句话结论告诉用户。
- 设置页的测试提示词改为先调用 `studio_status`。

**真实客户端验证**

| 客户端 | 方式 | 结果 |
|---|---|---|
| Codex CLI 0.163.0（本机 Codex 桌面版自带） | `tests/check-codex-mcp.py`，使用临时 `CODEX_HOME`，不调用模型 | **通过**：发现 17 个工具，完成 20 次调用（含 `studio_status`、导入制作包、编辑、撤销、`apply_nodes`），用户自己的 Codex 配置未改变 |
| Claude Code 2.1.304（本机） | 用设置页“连接客户端”的同一套逻辑写入临时 `CLAUDE_CONFIG_DIR`，执行 `claude mcp list` | **✔ Connected**；画布未运行（端口 3999）时同样 ✔ Connected，旧版这时会失败 |
| 自写 MCP 客户端脚本 | 对正在运行的画布走完整 stdio 握手和工具调用 | 通过 |
| Claude 桌面版、WorkBuddy、Hermes、豆包 | — | **未做真实验证**。本机没有安装 WorkBuddy 和 Hermes；豆包只能在客户端界面里手动添加；Claude 桌面版没有在本轮重启实测。配置写入逻辑已有自动化测试覆盖 |

## 4. Skill 的实现方式

### 组成

```
integrations/
  skills/
    catalog.json              # Skill 清单与版本号（设置页据此显示“最新 / 可升级”）
    deepwhite-canvas/SKILL.md # 画布创作：连接、读写、连线、导入制作包、生成、反馈（v1.1.0）
    deepwhite-film/SKILL.md   # 全自动影视：创意 → 剧本 → 分镜 → 关键帧 → 视频（v1.0.0）
    deepwhite-avatar/SKILL.md # 全能数字人：口播稿 → 形象 → 分段视频/配音（v1.0.0）
  packages/
    film-short.json           # “导入画布”用的制作包：立项、剧本、角色、分镜表、6 个镜头
    avatar-talk.json          # 数字人制作包：立项、口播稿、形象、配音、4 段画面
```

- **Skill** 只是给智能体看的说明文档（`SKILL.md`），不包含可执行代码。它规定智能体按什么顺序调用哪些 MCP 工具，以及提示词怎么写。
- **制作包** 是一张画布的文字节点模板，支持 `{{主题}}` 这类变量。用户在客户端里说“导入画布”，智能体就调用 `list_canvas_packages` → `import_canvas_package`，生成一张新画布，再按 Skill 继续往下做。导入只写文字节点，不会触发生成；同一个 `operation_id` 重试不会重复创建。

### 安装到哪里（设置 → 外接智能体 → 连接客户端并安装 Skills）

| 客户端 | MCP 配置位置 | Skills 位置 | 方式 |
|---|---|---|---|
| Codex | `%USERPROFILE%\.codex\config.toml`（或 `CODEX_HOME`） | `.codex\skills\` | 自动 |
| Claude Code | `%USERPROFILE%\.claude.json`（或 `CLAUDE_CONFIG_DIR`） | `.claude\skills\` | 自动 |
| Claude 桌面版 | `%APPDATA%\Claude\claude_desktop_config.json`（商店版优先使用包内私有路径） | 在客户端内上传 | MCP 自动；Skills 需下载 zip 后手动上传 |
| WorkBuddy | `%USERPROFILE%\.workbuddy\mcp.json` | `.workbuddy\skills\` | 自动 |
| Hermes | `%LOCALAPPDATA%\hermes\config.yaml`（或 `HERMES_HOME`） | `hermes\skills\` | 自动（只编辑块写法的 `mcp_servers:`，其他写法改为手动） |
| 豆包 | 无本地配置文件 | 在客户端内上传 | 复制配置粘贴到豆包；Skills 下载 zip 上传 |

客户端位置表参考了 REA 的客户端适配规则（MIT 协议），只借用了位置信息。

**安全约束**

- 只有本机设置页可以发起写入：接口会校验 Origin 和 Content-Type。MCP 工具不能修改客户端配置。
- 请求里只能指定客户端和动作，不能指定路径或文件内容。
- 每次写入前，都会在原文件旁生成带时间戳的 `.deepwhite-backup-*` 备份，并保留其他设置。
- 如果客户端在写入过程中改了自己的文件，本次写入放弃，不覆盖客户端的新内容。

**版本与升级**

- 安装时，会在 Skill 文件夹里写入 `.deepwhite-skill.json`（记录版本号和各文件的 sha256）。
- `catalog.json` 里的版本号更高时，卡片显示 `v旧 → v新` 和红色的“升级 Skills”。
- 升级前会把旧文件夹（包括用户改过的内容）整体移到 `*.deepwhite-backup-*`，再安装新版本。

**新增或修改一个 Skill**：在 `integrations/skills/` 下建文件夹并写 `SKILL.md`，然后在 `catalog.json` 里登记 id、名称和版本。修改已有 Skill 时必须提高版本号，否则用户不会看到升级提示。发行包会把 `integrations/skills/` 和 `integrations/packages/` 一起打进去。

**验证**：自动化测试覆盖了安装、升级、备份用户修改、同名文件夹、手动上传的客户端和 zip 下载。真实 Codex 联调中，“导入制作包”通过。**还没有在真实客户端里让智能体按 Skill 跑完整条流程**（这需要接入模型推理，并且会产生生成费用）。

## 5. 删除内置助手，以及用 MCP 控制画布的评估

### 清理

- 删除了已经不加载的内置助手代码：`studio_agent.py`、`studio_agent_builtins.py`、`studio_agent_plans.py`、`static/studio-agent*.js/css`，以及只测试它们的用例和浏览器脚本。
- 旧画布里由内置助手生成的 Skill 节点仍然可以显示和编辑。原来那个已经失效的“继续对话”按钮换成了说明文字：“旧版内置助手生成。可直接编辑；如需继续，请在已连接的外接智能体中说明此节点。”
- 文字节点上“导入技能文件夹”的功能（`/api/studio/skills`，给语言模型节点附加说明）与内置助手无关，保留。

### 现有基础

- **传输方式**：本机 stdio MCP 桥接（只用 Python 标准库），通过 `127.0.0.1` 访问画布的 `/api/studio/control/call`，用本机控制 token 鉴权。token 不会出现在返回内容里。
- **安全机制**：
  - 写入要求先读取最新 revision（乐观锁），否则返回 409；
  - `operation_id` 保证重试不会重复执行，每次操作都有回执；
  - 最近一次结构编辑可以撤销；
  - 有任务正在运行时拒绝编辑；
  - 生成需要用户在画布上逐次确认，或给出限时授权（最长 30 分钟或 20 次）。

### 现在开放了哪些操作（17 个工具）

| 类别 | 工具 / 操作 | 本轮变化 |
|---|---|---|
| 读取 | `list_projects`、`list_canvases`、`get_canvas`、`list_models`、`list_assets`、`get_node_schema`、`studio_status` | 新增 `studio_status`；`get_node_schema` 新增 `connection_rules` |
| 创建 | `create_canvas`、`import_canvas_package`、`list_canvas_packages` | 新增制作包 |
| 编辑（`edit_canvas`） | 文字节点增改删、移动 | 原有 |
| | **重命名任意节点**（`rename_node`）、**删除任意节点**（`delete_node`，同时清理连线和分组引用；删除分组不删除其中的成员） | 新增 |
| | **连线**：从“只能文字连到图片/视频/语言模型节点”扩展为与画布前端完全一致的规则（文字/图片/语言模型/分组 → 生成节点；生成节点 → 下游生成节点或输出节点，禁止成环）；断开任意连线 | 扩展 |
| 生成节点 | `apply_nodes`（新建或通过 `target_node_id` 更新图片/视频生成节点） | 原有 |
| 执行 | `generate_node`、`get_generation`、`resume_generation`（受审批约束） | 原有 |
| 撤销 | `undo_edit` | 原有 |
| 反馈 | `submit_feedback` | 新增 |

### 建议下一步开放的操作（按优先级）

| 优先级 | 操作 | 原因 / 前提 |
|---|---|---|
| 高 | **智能画布**的读取与编辑 | 现在所有工具都只支持普通画布。智能画布的数据结构独立（`smart-canvas.js`，约 1.9 万行），需要单独实现适配层 |
| 高 | 新建图片/素材节点：引用已导入的 `version_id` | 现在参考图只能作为生成节点的 `references` 使用，没有独立的图片节点 |
| 高 | 读取画布当前的选中状态 / 打开某张画布并定位到节点 | 让用户能说“改一下我选中的这个”；需要前端通过 WebSocket 推送选中状态 |
| 中 | 调用已有工具节点：放大、裁剪、RunningHub/ComfyUI 工作流、MJ 动作 | 每个工具的参数和计费各不相同，需要逐个做 schema 和审批 |
| 中 | 分组 / 解组、自动整理布局（对应 LibTV 的 Alt+Shift+F） | 前端已有对应功能，需要搬到服务端 |
| 低 | 批量导出结果、下载生成文件到指定目录 | 涉及写入任意本地路径，需要先确定沙箱规则 |

### 范围限制（如实说明）

- “外接智能体可以完全替代内置助手”目前**还不成立**：智能画布不能被控制；工具节点不能被调用；WorkBuddy、Hermes、豆包、Claude 桌面版没有做真实连接验证。
- 生成始终需要用户在画布上授权，这是有意保留的设计。
