首次安装：下载 `portable.zip`，完整解压到可写目录，双击 `Start.cmd`。自带 Python，不必安装开发环境。不要下载 Source code 或只含更新版本的 `version.zip` 来代替完整包。

旧便携版：在设置进入版本更新，依次检查、下载；保存并关闭其他画布标签页后安装。旧 .16 的入口在“基础设置 → 关于 → 版本更新、安装与回退”，新版在“存储与更新”。如出现“完成更新并重启”，点击并确认，等待新版启动器自动启动。程序不会按名称强杀其他进程。

Codex：在同一台 Windows 运行 Codex 与画布，打开“设置 → 外接智能体 / MCP”，启用访问、点击“自动配置 Codex”，检查后重启 Codex 的 MCP 连接，发送页面测试提示词。配置自动采用客户自己的安装和用户目录。[完整步骤](客户安装与Codex连接.md)。

## .5 的实际验收发现与修复

最初 .5 完整包通过本机安装和真实 Codex 验收；首次公开 HTTPS 下载、安装、备份、回退也通过。进一步重启到 .5 的启动器，再回退 .16 和安装 .5 时，更新器先移动已有 .5 目录，使正在运行的 Python 无法加载标准库 `encodings.cp437`，解压失败。这不是磁盘不足或模拟失败，真实异常链与失败测试均保留。

因此 .5 已退出稳定推荐、标记预发布，默认 stable 暂回 .16。没有覆盖或删除 .5 附件、标签和源码历史。修复版 .6 对已有版本做签名包完整对照后原地复用，绝不移动运行时；HTML 改为响应时版本化；旧式工作流数据写 userdata；并加入更新后的安全重启入口。

.5 历史来源 `6222ab7707f01e767bf15d0f6e489383421052c6`；portable SHA-256 `735574df06a1eddd2abc446f5fbd7cbfdc8fd4615e80e7ae24ae474cace51905`，version SHA-256 `6e2132a15048c166b8bb7fbfb858f79fc692e8fea4efd9f7e1309d2c6ea775cc`。失败记录不计入 .6 通过数。

## 数据、兼容与维护

安装前停止本安装服务、备份并校验独立 `userdata`，再切换程序。成功后的手动回退保留最新项目；失败回退在恢复编辑前恢复更新前备份。外部素材、浏览器未保存草稿需自行保存；源码运行版仍通过 Git 更新。

画布 schema 1 不变，画廊仍为 0.4.0/schema 4。新增 `userdata/data/legacy-workflows` 在回退旧程序时仍保留，但旧程序不读取；再次升级后恢复显示。已保留旧版本中的 custom/自定义 工作流只读兼容。若同名版本文件被改动，更新器停止覆盖；请保留整个安装目录，按 [维护与恢复说明](Windows发行与更新.md) 使用新完整包。

更新私钥只在维护者机器，不上传源码或附件。签名清单有有效期，维护者需在到期前用递增序号发布/续签，详见维护说明。更新 Ed25519 签名不等于 Windows Authenticode 或 SmartScreen 信誉。

## 验证方法与边界

`scripts/check_public_release.py` 从公开地址下载旧、新完整包，通过产品 API 实际从空更新缓存下载签名版本包，验证安装、备份、用户数据、新版启动器、回退和再升级。测试必须先重启到新启动器，再执行回退/重装，不能只在旧 supervisor 中完成循环。通过标签清单验收后，再用 `--verify-stable-existing` 删除仅属于测试的覆盖，验证原生默认 stable。

所有验收使用独立安装、隔离 Codex 配置与合成项目；不改真实用户配置、不调用收费模型。模拟故障、真实下载、真实进程/客户端和浏览器结果分开记录；物理异机、企业策略、物理断电、真实付费生成和公网画廊仍未验收。完整能力和缺口见 [.6 累计状态](../app/docs/releases/0.11.0-studio.6-status.md)。
