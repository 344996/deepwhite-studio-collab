## RunningHub

### 问题04 RH-CONNECTION-FALSE-POSITIVE 鉴权失败仍显示连接成功

**原因**：拉取模型目录时，OpenAPI 返回 401 后会回退到公开的 GitHub 或本地目录，而连接测试固定返回 `ok: True` 和“OpenAPI 可用”。

**修改**（`main.py`）：
- 目录拉取时记录 OpenAPI 的 HTTP 状态。
- 连接测试分阶段报告：`stages = {service, auth, auth_status, catalog}`。
- 判定规则：
  - 401/403：鉴权失败，`ok=false`。提示“鉴权失败（HTTP 401）……模型目录仍可从公开 GitHub 注册表读取，这只说明目录可读，不代表连接成功”。
  - 2xx：鉴权通过。提示中同时说明目录来源，并说明具体应用和工作流的权限会在运行时再核对。
  - 无法连接：显示“未能核实”。

**回归**：`tests/test_runninghub_probe.py`，包括 401 加公开目录 200、有效 Key、服务不可达三种情况。

**限制**：不会预先核对某个具体工作流的权限，这一点仍在运行时校验。

### 问题05 RH-APP-DEMO-SHAPE 只有 curl 的官方样例形状未兼容

**原因**：`apiCallDemo` 的官方样例只在 `curl` 字符串的 JSON 请求体里给出参数，没有单独的 `data.nodeInfoList`。

**修改**（`main.py`、`studio_rh_workflows.py`）：
- `runninghub_app_info` 分三种情况处理：
  - 有 `nodeInfoList` 时直接使用，`fieldSource` 记为 nodeInfoList。
  - 只有 `curl` 时，只从字符串中解析出 JSON 请求体，取其中的 `nodeInfoList`，绝不执行命令，`fieldSource` 记为 curl。
  - 两者都没有，或 JSON 无法解析时，返回 400 和具体诊断：“RH 应用信息中没有可识别的参数……”。
- 返回的 `curl` 中的 `apiKey` 会被隐藏。
- 预览接口会在 `diagnostics` 中写明“参数来自 RH 官方 curl 示例中的 JSON（只解析，未执行命令）”。

**回归**：结构化形状和 curl-only 形状都能提取出参数；预览能显示来源；空数据和畸形 curl 都给出具体诊断。

### 问题09 LINK-01 经典文字节点价格区出现后连线脱离端口

**回归**：`tests/check-classic-canvas-fixes.cjs`，用真实页面测试。

- 修复后：价格区出现、切换模式、缩放，每种情况下连线起点与实时端口的偏差都 ≤1.5px。

## 任务与对账

### 问题13 TASK-01 生成已启动但审批回执写盘失败，关联可能断开

**原因**：上游任务已经受理，接着写回执失败，记录停留在 submitting 状态、没有 job_id，再次请求只能返回“待核实”。

**修改**（`studio_control.py`、`studio-control.js`）：
- 任务本身以 `request_id` 为编号保存。回执写入失败时，不再报 500，而是返回 `receipt: "failed"`，并提示“任务已提交（编号 X），但本地回执未能写入……不会重复提交”。
- 再次请求同一个编号（`_generate` 或 `_approve`）时，会从原任务文件重建回执，返回 `recovered: true`，不会提交第二个任务。
- 审批界面会分别显示“回执失败”和“已按原编号找回”。

**回归**：`test_studio_control` 新增 1 项。批准后让回执写盘失败，结果中能看到原编号；再次批准和再次生成都恢复同一个任务，上游只被提交了 1 次。

### 问题24 LIVE-LLM-01 文字生成未透传输出 Token 上限

**原因**：文字模型的参数在净化后变成空对象，请求体里只有 model、messages、stream 三项。

**修改**（`studio_capabilities.py`、`studio_generation.py`）：
- 文字模型可以设置 `max_tokens`（1–128000 的整数）和 `temperature`（0–2）。越界或格式不对时明确拒绝，不再静默丢弃。
- 请求体按协议写入：
  - 普通模型使用 `max_tokens`。
  - 推理模型（o 系列、gpt-5）使用 `max_completion_tokens`，回执中记录这个上限包含思考 Token。
- 推理模型如果设置了温度，明确拒绝。

**回归**：`tests/test_generation_llm.py`。
- `max_tokens=16`、`temperature=0` 都出现在最终请求体中。
- 推理模型的请求体使用正确的字段。
- 非法值都被拒绝。

### 问题25 LIVE-LLM-02 LLM 成功回执缺少上游标识与金额对账信息

**修改**：
- 成功时保存响应的 `id`（`upstream_response_id`），以及 `x-request-id` 或 `request-id` 响应头（`platform_request_id`）。失败时同样保存这两个标识。
- `billing` 字段分两种：
  - 平台返回了金额和币种：记为 `reported`，保存平台给出的数值。
  - 没有返回：记为 `pending`，并注明“待与账单核对；不是 0 元”。
- 界面文字从“实际费用未知”改为“实际费用待对账 · 平台未返回金额（不是 0 元）”。估价和实扣分开显示。

**回归**：
- 成功和失败的响应都保留了标识。
- 有金额和无金额两种情况都按上面的规则记录。
- 记录里没有出现 Key。

### 问题28 REF-03 最终上游请求缺少与素材身份、上传哈希的可复核关联

**修改**（`studio_generation.py`）：在真正发出 POST 之前，把一份脱敏快照写入任务子记录的 `submission` 字段，内容如下：

| 字段 | 内容 |
|---|---|
| 记录类型 | `local_before_send` |
| 请求标识 | 任务 ID、模型、请求版本（`SUBMISSION_VERSION`）、接口 |
| 每个素材（按实际顺序） | 位置、类型、标签；原路径，公网 URL 去掉查询串；本地文件的 sha256；上传后的地址，去掉签名查询串 |
| 请求体 | 请求体 sha256 |
| 说明 | 本地发送前记录，不能证明平台实际收到完全相同的字节 |

**回归**：快照中的编号、顺序和哈希都能对应上；回执里没有出现 Key 和签名参数。

**限制**：
- 任务请求中仍保存用户原样提供的公网 URL，执行时需要它。
- 原有的上传缓存为了复用，会在本机保存最长 24 小时的签名地址。这一点没有改动。

## 价格显示

### 问题18 PRICE-01 香蕉 2K 估价仍按 1K 显示

**原因**：`deepwhiteai-image-nb-2.1-lowprice` 的“历史估价”只有一条不区分分辨率的样本（¥0.072）。而“同参数历史账单”按分辨率给出了 1K ¥0.072、2K ¥0.096、4K ¥0.12，原代码总是优先使用前者。这是用 2026-10-24 公开定价接口核对得出的。

**修改**（`studio_pricing.py`）：如果账单证据区分了某个估价忽略的收费维度（例如分辨率），而且本次请求指定了这个维度，就改用账单证据。没有对应样本的规格（例如 0.5K）显示“暂无可靠估价”。

**回归**：`tests/test_pricing_estimates.py`。
- 1K、2K、4K 分别为 0.072、0.096、0.12，0.5K 显示未知。
- 已按分辨率区分的模型和单一价格的模型结果不变。
- `check-commerce` 也通过。

### 问题19 PRICE-02 余额显示 CUSTOM 而不是币种符号

**原因**：账号余额会按站点的 `quota_display_type` 和 `custom_currency_symbol` 解析出符号；API Key 钱包则把 `display_type` 原样显示出来。

**修改**（`studio_account_extension.py`、`studio-account-skills.js`）：
- Key 钱包遇到 CUSTOM 时，读取账号余额所用的同一份公开站点设置，取其中的符号。站点没有提供符号时，不显示单位，并说明原因。
- CNY 和 USD 照常显示代码。
- 金额数值不做转换。界面上，符号放在数字前，单位代码放在数字后。

**回归**：`test_studio_account` 新增 1 项，覆盖 CUSTOM 有符号和 CUSTOM 无符号两种情况。原有的 CNY 用例也通过。

### 问题20 UX-01 低缩放时提示词编辑区无法舒适阅读

**修改**：新增 `static/studio-focus-edit.js`，两个画布共用。

### 问题23 UX-03 弹层进入动效缺少统一规则

**修改**：新增 `static/studio-motion.css`，在两个画布中最后加载。规则如下：

| 类别 | 时长 | 覆盖范围 |
