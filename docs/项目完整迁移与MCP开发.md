## 本批新增

已有九个 MCP 工具保留，新增四个，总计十三个：

| 工具 | 功能 |
| --- | --- |
| `list_projects` | 读取本地项目及项目列表版本 |
| `get_node_schema` | 读取可操作的节点、参数和限制 |
| `create_canvas` | 在已有项目里新建普通画布，返回可打开的网址 |
| `edit_canvas` | 一次提交文字增改删、移动普通节点、连接或断开文字输入 |

文字可连接图片生成、视频生成或语言模型节点；图片/视频节点的创建仍使用原有 `apply_nodes`。新操作不会调用生成服务。设置 → 本地智能体（MCP）明确展示编辑能力，用户自行启用、复制连接配置；本次没有更改用户的 Codex 配置，也没有默认开启 MCP。

文字删除同步清理普通分组和提示词分组的引用。修改被当作一次完整操作保存；`undo_edit` 可撤销最近一次结构编辑，但遇到后续内容修改或活动任务时拒绝覆盖。

## 调用与保护

1. `list_projects` 得到项目编号和版本；把版本作为 `create_canvas.expected_revision`，为每项意图生成独立 `operation_id`。
2. `get_canvas` 获取最新图内容和 revision；`get_node_schema` 获取当前操作格式。
3. `edit_canvas` 提交编辑；同批新增节点可以用 `$key` 连接。下面是 operations 的例子，目标生成节点必须已存在。

```json
[
  {"op":"add_prompt","key":"story","text":"雨后的城市街道，人物缓缓走近。","x":60,"y":100},
  {"op":"connect","from":"$story","to":"existing_generator_id"}
]
```

重试应发送相同的 operation_id 和原内容。相同编号不同内容返回 409；成功操作重放返回原结果（即使随后已撤销），不会重新编辑。返回的 revision 是该操作当时的版本，下一次编辑前应重新读取。新画布若已回收或永久删除，不因重试重新创建。

结构编辑日志与节点在同一次原子文件替换中提交；原生浏览器保存保留日志。画布复制/导入更换编号后，不继承原画布的重试和撤销权限。创建画布使用独立预约记录：明确落盘失败且确认无画布时允许同编号重试；进程突然中断、结果不明或连失败标记都无法保存时保留现场并要求先核对，防止重复创建。

两种入口（HTTP 控制和 stdio MCP）都校验结构、字段、有限坐标、文字长度和数量；继续要求本机访问、控制启用与独立令牌。存在运行、排队、暂停或结果待核实任务时拒绝结构编辑与撤销。付费生成仍需已有逐次审批或用户限时授权。

限制：本批仅普通画布；文字最长 20,000 字，单批 1–40 项、256 KB；可编辑画布最多 1,000 节点和 4,000 连线；每幅画布保留最多 2,000 次结构编辑结果，达到上限拒绝新增操作。只保留最新结构编辑的完整撤销快照，不提供无限历史撤销。任意节点增删、媒体导入、项目管理和智能画布 MCP 尚未扩展。

协议沿用已实现的版本协商，测试客户端请求 2025-11-25，服务协商返回 2025-06-18；未宣称完整实现新版规范或任意 Codex 客户端验收。结构化结果和工具输入的设计参照 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) 与 [版本协商规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)。
