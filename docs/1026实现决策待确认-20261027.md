## 1. U01 登录后直接调用官方 API

**现状（已核对代码）**：登录后获取生成授权的链路已经实现，并非缺少接口。`studio_account_provision.py` 在登录会话内调用 New API 的令牌接口：

- 按安装名查找令牌：`/api/token/search`
- 没有就创建：`POST /api/token/`
- 取出密钥：`/api/token/{id}/key`

拿到的密钥只保存在内存会话里，磁盘上只记令牌编号。随后自动建立 `deepwhite-account-…` 渠道、设为默认，并同步模型。退出、切换账号和两步验证都有自动测试覆盖。

**用户截图的情况**：设置页显示的是手动的“DeepWhite API · 默认”，提示“尚未保存密钥”。说明这次登录后，账户授权没有成功建立；如果成功了，设置页会默认显示账户渠道，并写明“由登录账户自动管理”。可能的原因：
- 令牌接口拒绝了请求（账号权限或接口版本不同）；
- 登录后没有触发授权（例如通过网页登录，而不是软件内登录）。

我不能代替你登录（不能输入密码），所以没有复现。

**推荐**：
1. 你在软件内登录一次，打开设置 → 账户与 API，把账户卡片上的提示文字发给我，或打开 `http://127.0.0.1:3848/api/studio/account` 把 `generation.status` 和 `generation.message` 两项发给我。注意不要发密钥。
2. 我会把“登录了但授权没建立”的状态改成显眼的提示和“重新授权”按钮，同时不再让手动渠道的“请先填写 API Key”成为首先看到的内容。

**需要你回答**：令牌的有效期和额度上限，软件是否需要设置（目前创建的是不过期、额度不限的令牌，额度以账号余额为准）？

## 2. U06 LibTV 接入

**现状**：代码里没有任何 LibTV 的接口或协议资料，`references/` 里也没有。

**可选方案**：

|方案|能做什么|前提|
|---|---|---|
|A 官方 API|在画布中提交、查询 LibTV 生成任务，与 RH 一样记账|LibTV 提供公开 API 文档和 Key|
|B 账号授权|使用用户的 LibTV 账号生成|LibTV 提供 OAuth 或令牌接口|
|C 本地桥接 / CLI|调用本机 LibTV 程序|LibTV 提供 CLI 或本地服务|
|D 只打开网站|设置页提供“打开 LibTV”链接|无|

**推荐**：拿到正式协议之前只做 D，页面写明“未接入，不支持自动生成”（样式页 U06 → LibTV 已按此展示）。RunningHub 的设置整合（U07）不依赖 LibTV，可以先做。

**需要你回答**：LibTV 要接的是 A、B、C 中的哪一种？有没有官方文档或联系人？

## 3. U10 删除智能画布

**现状**：智能画布和经典画布的项目数据格式不同（智能画布有智能分组、批次参数和自己的节点类型），没有现成的转换器。

**可选方案**：

|方案|旧项目怎么处理|工作量|风险|
|---|---|---|---|
|A 只读保留|首页单独分组，只能查看和导出，不能编辑|小|用户不能继续编辑旧项目|
|B 迁移到经典画布|先备份，再生成经典画布副本；不能转换的节点改为备注节点，原始数据作为附件保留|中到大|个别节点类型会丢失交互能力|
|C A+B|默认只读，用户可以逐个确认后迁移|中到大|无额外风险|

**推荐 C**：首页、菜单和快捷键都不再新建智能画布；旧链接打开只读页，页面上提供“导出”和“迁移到经典画布”两个按钮（样式页 U10 已按此展示）。任何情况下都不删除旧项目文件。

**需要你回答**：
- 选 A、B 还是 C？
- 只读入口保留多久？
- 有没有必须能迁移的节点类型？例如 RH 节点、MJ 节点、批次节点。

## 4. U11 删除 Skills

**现状**：软件内有三组 Skills（画布创作、全自动影视、全能数字人）。代码会展示它们，也会安装、升级、修复，并提供压缩包下载；安装时写入各客户端的 skills 目录。这一轮已修好"升级失败不恢复"（SKILL-ROLLBACK）。

**可选方案**：
- A：只删除软件里的 Skills 展示和安装、下载入口，用户已经装到客户端里的文件不动。
- B：在 A 的基础上，提供一个"卸载 DeepWhite Skills"按钮，由用户手动点击。只删除带 DeepWhite 标记、且未被用户修改的副本；被修改过的先备份。
- C：自动删除已安装的文件。

**推荐 A**。报告也写明"默认不动用户全局或自定义技能"，C 不建议做。

**需要你回答**：选 A 还是 B？
