# 0.11.0-studio.5 客户接入与 Windows 发行

日期：2026-10-21。客户操作见 [安装与 Codex 连接](客户安装与Codex连接.md)，累计功能见 [本版状态](../app/docs/releases/0.11.0-studio.5-status.md)。

本轮完整包包含客户 Codex 自动配置，以及 .2/.3/.4 的生成记录、工作台和交互反馈改进。应分发 `deepwhite-0.11.0-studio.5-windows-x64-portable.zip`，不能把开发目录或 GitHub 源码 ZIP 当成客户安装包。

## 产物与来源

本机交付产物目录为开发工作区的 `release-0.11.0-studio.5-r2/`：

- `deepwhite-0.11.0-studio.5-windows-x64-portable.zip`：完整解压后双击 `Start.cmd`，自带运行环境。
- `deepwhite-0.11.0-studio.5-windows-x64-version.zip`：更新器的版本包。
- `update-stable.json`、`SHA256SUMS.txt`、`build-report.json`：签名清单、文件校验与源码提交记录。

构建只使用 Git 已提交源码。运行时为官方 Python 3.13.16 嵌入式解释器和 28 个锁定 wheel，本版增加保留 TOML 格式的 `tomlkit==0.13.3`；构建核对来源/摘要并使用包内解释器检验导入与更新清单签名。私钥和用户数据不随包分发。

本轮没有创建公共 GitHub Release 或更改线上 stable 更新源。仅更新 main 不会让旧客户自动收到新版；本地完整包可单独交付客户测试，公开发布需要实际上传对应产物。

## 验证记录

源码配置与 HTTP 边界 18 项、MCP 诊断/固定入口 9 项、控制器 19 项、发行构建 13 项通过。配置测试使用独立 `CODEX_HOME`，包含原偏好/注释保留、异常格式、乱序表、旧连接确认、幂等、并发修订、失败原子性、损坏撤销记录和提交后中断恢复。

界面模拟接口的 8 组场景通过，覆盖安装/重试、取消替换、撤销、诊断、生成审批、键盘和窄屏。另外 5 组真实浏览器→后端→MCP 桥接联调通过，确认浏览器自动携带的 Origin、配置写入、中文/空格临时目录、五层桥接检查与原文件逐字节撤回；两类浏览器验证均无脚本错误。实际 ZIP 验收由 `scripts/check_current_release.py` 和 `scripts/check_customer_mcp_release.py` 独立执行。

构建后的实际产物摘要、界面结果和 ZIP/客户端验收记录由后续证据提交补充；包内文档保留构建时的源码语境。以 `build-report.json` 的 commit 和同目录 `SHA256SUMS.txt` 对应实际文件，不能把以前版本的测试视作本次通过。

第一次本地 `.5` 构建保留在 `release-0.11.0-studio.5/` 作为失败样本，不得交付。该包虽通过基础启动及一次性桥接检查，真实 Codex 却握手超时：PowerShell `CopyToAsync` 未逐段刷新，stdin 保持打开时小请求停留在缓冲区。新回归先复现失败，再验证逐段刷新的并发字节流；实际 ZIP 验收脚本也改为逐条请求等待响应、全程保持 stdin 打开。失败证据保留于 `customer-mcp-verification-studio5/`，修复包使用独立的 `-r2` 构建与验证目录。

## 范围与恢复

没有付费生成、API 网站登录或真实 GPU 运行；客户的物理电脑、企业策略、远程/WSL 环境、生产画廊和长期大画布性能未因此完成验收。Windows 更新清单签名也不等于 Authenticode。

画布继续使用独立 `userdata/`，无 schema 迁移。Codex 原配置留在客户自己的配置目录备份，界面可撤销上次深白连接修改；不会恢复覆盖其他后续偏好。维护者真实 Codex 配置不用于安装测试。
