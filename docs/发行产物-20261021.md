## 验证记录

源码配置与 HTTP 边界 18 项、MCP 诊断/固定入口 9 项、控制器 19 项、发行构建 13 项通过。配置测试使用独立 `CODEX_HOME`，包含原偏好/注释保留、异常格式、乱序表、旧连接确认、幂等、并发修订、失败原子性、损坏撤销记录和提交后中断恢复。

界面模拟接口的 8 组场景通过，覆盖安装/重试、取消替换、撤销、诊断、生成审批、键盘和窄屏。另外 5 组真实浏览器→后端→MCP 桥接联调通过，确认浏览器自动携带的 Origin、配置写入、中文/空格临时目录、五层桥接检查与原文件逐字节撤回；两类浏览器验证均无脚本错误。实际 ZIP 验收由 `scripts/check_current_release.py` 和 `scripts/check_customer_mcp_release.py` 独立执行。

重建后的实际 ZIP 基础验收 **8 组通过**：文件摘要、包内文档与数据洁净、独立环境启动、保存及读取中文节点、产品页面与移除的助手入口、固定 MCP 入口、13 个工具发现和重启后数据保留。

客户接入专项 **15 组通过**：空白配置、已有偏好/注释/其他 MCP 的保留、备份/幂等/撤销、Origin 与并发保护、持续连接、目录搬迁后的确认更新、再次重启和损坏 TOML 拒绝。实际 `codex-cli 0.163.0-alpha.10.2` 的 app-server 在搬迁前后两个安装位置均发现 13 个工具，并成功调用 `list_projects` 与 `get_node_schema`；直接 stdio 还读取了保存的测试画布。所有协议请求逐条等待响应，保持 stdin 打开。没有调用推理模型或收费生成。

两个安装位置均包含中文、空格及特殊字符；启动时 PATH 无系统 Python，使用包内环境。新用户目录和已有配置均为隔离测试；真实用户配置哈希保持不变。测试结束后按归属停止测试服务，工作区与失败材料保留。

结构化结果见 [本次验证 JSON](verification-customer-mcp-20261021.json)。原始证据位于开发工作区的 `evidence/customer-portable-studio5-r2/verification.json`、`customer-mcp-verification-studio5-r2/verification.json`、`initial-codex.json`、`moved-codex.json` 和对应 `*-stdio.json`。包内文档保留构建时的源码语境；本页记录构建后的最终验收。以 `build-report.json` 的 commit 和同目录 `SHA256SUMS.txt` 对应实际文件，不能把以前版本的测试视作本次通过。

## 范围与恢复

没有付费生成、API 网站登录或真实 GPU 运行；客户的物理电脑、企业策略、远程/WSL 环境、生产画廊和长期大画布性能未因此完成验收。Windows 更新清单签名也不等于 Authenticode。

画布继续使用独立 `userdata/`，无 schema 迁移。Codex 原配置留在客户自己的配置目录备份，界面可撤销上次深白连接修改；不会恢复覆盖其他后续偏好。维护者真实 Codex 配置不用于安装测试。
