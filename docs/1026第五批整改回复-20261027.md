## 各项说明

### U01 登录后直接调用官方 API

**现状**：第 7 节第 1 项已核实，登录后取得生成授权的链路（New API 令牌接口）原本就已实现。用户截图里那次登录没有建立授权，原因需要真实账号才能确认。

**这一批的改进**（`studio-settings.js`）：
- 已登录但授权未完成时，账户卡片改为警示样式，标题写明“生成授权未完成”，显示失败原因，主按钮为“重新授权”。
- 打开设置页时自动重试一次授权（每个会话一次）。这一步只创建或读取账户自己的 API 令牌，不生成内容、不扣费。
- 授权正常时，标题写明“可直接生成，无需填写 API Key”。

**用例**：`check-account-authorization.cjs` 共 4 项，账户接口在浏览器中模拟。

**待验证**：真实账号登录、续期、退出、切换账号。

### U02 豆包工作

客户端卡片改名为“豆包工作”，并提供手动粘贴的 MCP 配置和验证命令。目前只检测 `%LOCALAPPDATA%\Doubao\Application\*.exe`。“豆包工作”真实的安装位置和配置方式仍需要你提供。

### U03 生成结果节点默认折叠（含 UI-NEW-01/02）

**实现**（`studio-result-collapse.js`、`.css`）：
- 在经典画布上，已经有结果的图片或视频生成节点，未选中时只显示：结果、名称、状态行（生成中、失败原因等）。
- 只有当它是唯一被选中的节点、你最近操作过它（例如刚在其中点了“生成”），或你正在其中输入时，才展开提示词、参考素材和参数。
- 撤销或画布重绘不会把正在编辑的节点收起；点画布空白处、选中其他节点或多选时才收起。
- 折叠只是隐藏，不清空文字；还没有结果的节点照常显示编辑区。

**用例**：`check-result-collapse.cjs` 共 7 项，全部用真实鼠标点击。覆盖：
- 失败状态在折叠时可见；
- 输入的文字在折叠后保留；
- 多选；
- 展开和收起后连线仍对准端口；
- UI-NEW-02：在 1280×800、视口 x=525/y=−128 下，点击每个可见节点都选中正确的节点。被顶部固定栏遮住的部分不算可点击区域，这属于正常遮挡。

**说明**：
- 第四批已经修复了“节点自动加宽后盖住相邻节点”。
- 智能画布上的同类遮挡（`check-smart-v2`、`check-smart-overlay-layout`）随 U10 处理，没有修改。

### U04 默认常用模型

**实现**：
- 新增 `studio_favorites.py`，服务器端保存常用模型，键为“渠道|型号”，同一型号在不同渠道可以区分。
- `studio-models.js` 的模型选择器：
  - 增加“常用 / 全部模型”切换；
  - 每行增加 ☆；
  - 常用模型可以跨渠道显示；
  - 已停用的常用模型会显示，并标注“已停用或当前不可用”。
- 收藏只影响选择器，不会修改已有节点。

**偏离推荐方案**：
- 有常用模型时，选择器默认打开“常用”。
- 还没有常用模型时，默认打开“全部模型”，并显示提示“点 ☆ 加入常用”。
- 原因：如果没有常用模型也打开空的“常用”页，每次都要多点一次才能选到模型。

**用例**：`check-model-favorites.cjs` 共 6 项。原有的 `check-model-picker-ownership`、`check-compact-generation` 仍通过。

### U09 删除常驻字数说明

**实现**（`studio-stage-one.js`）：
- 去掉常驻的“提示词 N 字 · 要求 …”。
- 只在点生成时就地提示：
  - 为空：“请先填写提示词”；
  - 太短：“至少需要 N 字”；
  - 超长：“当前 N 字，超过此模型上限 M 字；请删减后再生成，已输入的内容会保留”。
- 不放宽后台限制，也不截断文字。
- @ 引用素材缺失等其他错误，仍然立即显示。

**用例**：`check-prompt-hint.cjs` 共 4 项。原有 `check-stage-one` 中两处断言改为点生成后再检查。

### U10 删除智能画布

**实现**：
- 首页的新建对话框只能新建普通画布（`studio-home-v2.js`）。
- MCP 的 `create_canvas` 只允许普通画布。
- 首页的旧智能画布标为“旧版智能画布”。
- `deepwhite-canvas` Skill 说明改为“智能画布已停止新建，建议迁移”，版本升到 1.2.1。
- 新增 `studio_smart_retire.py`，迁移方式：
  - 先把原画布完整备份；
  - 再复制为新的经典画布：提示词节点变为文本节点，有图片的节点变为图片或结果节点，没有对应的节点（分组、循环等）变为说明节点；
  - 每个节点都保留原始数据（`legacySmart`），连线一并迁移；
  - 原画布不做任何改动，重复迁移返回同一个副本。
- 智能画布页面增加可收起的提示栏：“迁移到经典画布”“导出”。

**偏离推荐方案**：
- 旧智能画布仍然可以编辑，没有改成只读。
- 原因：报告第 6 节 U10 的验收要求是“不再推荐、旧链接有明确处理、旧项目可找回、经典流程不受损”，并不要求只读。
- 改成只读需要改动 22 个智能画布测试，也可能影响用户尚未保存的内容。
- 如果需要只读，可以在退役期结束后再切换。

**用例**：
- `test_smart_retire.py` 共 5 项，覆盖转换内容、原画布不变、备份、重复迁移、MCP 拒绝新建；
- `check-smart-retire.cjs` 共 5 项。

### U11 智能体连接

**实现**：
- 页面只显示 Codex、Claude Code、WorkBuddy、豆包工作、DeepSeek Harness 五个客户端。
- Hermes、Claude 桌面版不再显示，但仍可以通过接口连接。
- DeepSeek Harness 暂时不能自动检测，显示“不支持自动检测”，并提供手动配置。
- 每个客户端有一个验证码。复制的验证命令要求智能体调用新的只读工具 `verify_client`，这个工具只返回最近一个画布的名称和节点数。
- 服务端收到验证码后，页面自动显示“已验证”。重新连接后需要重新验证。
- 页面不再展示 Skills 及其安装、下载入口。用户已经装在客户端里的 Skill 文件不会被改动。

**用例**：
- `test_external_agents` 新增 2 项；
- MCP 工具数量从 17 改为 18，相关 3 个用例同步更新；
- `check-client-cards.cjs` 改写为 5 项，用真实的“一键连接”，再用验证码调用真实的控制接口。

**待验证**：五个真实客户端的连接与回读。

### REF-03 RH 记录与素材追踪统一

**实现**（`studio_runninghub.py`、`main.py`）：
- 每次上传到 RunningHub 时，记录这个 RH 文件名来自哪个本机文件或素材版本，以及它的 SHA-256。
- RH 账本在付费提交前写入 `submission`：每个素材字段的来源、素材版本、SHA-256、RH 文件名，以及请求体的哈希。
- 不记录密钥和签名链接。查不到来源的 RH 文件名会原样列出，但不编造来源。

**用例**：`test_rh_submission_trace.py` 共 2 项。

## 测试用例与环境的调整

- **跟随新行为修改的旧用例**：
  - `check-stage-one`：在已经有结果的节点上编辑前，先点选节点（U03）。
  - `check-canvas-save-safety`：字数提示改为新文案（U09）。
- **早已过时的性能用例**：`check-canvas-performance`、`check-workspace-performance` 在合并后的 main（`79b939e`）和第四批代码上同样失败，不是这一批引起的。原因是画布从最初版本起就是“滚轮平移、Ctrl+滚轮缩放、Ctrl+拖动框选”，而这两个用例还在用普通滚轮缩放、普通拖动框选，并且框选起点落在了顶部栏下面。已改为 Ctrl 操作，并先把视图移到开阔处；性能指标的断言没有放宽。
- **`check-canvas-link-geometry`**：单独运行通过；在全量连续运行、机器负载高时偶尔有一步超时。断言失败信息现在会写明是哪一步、偏差多少，方便以后定位。
- **改用固定视频素材**：`check-native-tasks-integration`、`check-smart-notices` 原本在浏览器里现场录制视频；在无头浏览器高负载时有时录到空文件，导致测试不稳定。现在改用一段事先录好、确认能解码的 320×180 WebM 文件（`tests/fixtures/native-fixture.webm`）。
